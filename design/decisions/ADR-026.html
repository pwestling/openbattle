ADR-026: True line of sight, any part to any part

Status
Proposed Porter asked on 2026-10-17 for line-of-sight handling to be built, so that rules automation can use it. This takes "Line-of-sight checks" off the intent's list of what is not in the first version.
Context
In OnePageRules, shooting, spells, a caster's helpers within 18″ and cover ("behind sight blockers") all depend on what a model can see. Model bodies and terrain are already true 3D shapes (ADR-019), so the table can answer this exactly, where on a real table players crouch and argue. A rules package should not work out sight lines through meshes itself: that is geometry, which Measure hides.
Decision
  • A new concept, line of sight, answered by a new Measure operation and a new gesture on the screen.
  • A model sees a target if any part of its body can see any part of the target's body (true line of sight). The answer also gives how much of the target is seen and which pieces hide the rest, so a package or the players can judge cover from it.
  • Everything is in the way by default: every terrain piece and every other model. Whoever asks names the pieces that don't count. That is how a package makes only sight-blocking terrain count, using the terrain marks being drafted alongside this.
  • Bases are left out: they don't see, aren't seen and don't block.
  • Every browser must have every mesh on the table before it answers, so that everyone gets the same answer.
Because
Any part to any part is the most common true line of sight convention, needs nothing the table doesn't already have, and is symmetric, so "A sees B" and "B sees A" never disagree. Returning what is in the way, rather than a yes or no under fixed rules, keeps Measure free of any one game's rules: each package decides what blocks and what counts as cover.
Rejected
  • Sight from the model's eyes, or from a fixed height above its base: meshes don't say where the eyes are, and players would have to place them.
  • Only terrain blocks: many games, OnePageRules included, let models hide behind other models. A package that disagrees can ignore models.
  • A yes or no only: cover needs to know how much is hidden and by what.
  • Sight worked out by the screen from what it draws: the drawing is not the same in every browser and is not something a package can call.
  • Checking only from the base's centre, or along the table top in 2D: wrong for tall terrain, floors and big models, which the table models in 3D on purpose.
