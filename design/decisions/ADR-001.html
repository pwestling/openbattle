OpenBattle design · Level 0 · Decision

ADR-001: The engine knows physical things and a few shared rules ideas; rules packages come later

Status
Accepted Rewritten from Porter's review on 2026-10-14. Accepted by Porter on 2026-10-14.
Context
Porter wants rules automation from packages eventually. Nearly every wargame shares a few rules ideas beyond the physical table: units and groups of units, phases, and numbers and states on things. The first attempt built a general package runtime (sandboxes, replayed scripts, hooks, branches) before any one game was pleasant to play.
Decision
The engine knows the physical table (terrain, models, dice, measuring) plus units, groups, phases, counters and marks (and, since 2026-10-17, priority and items: ADR-026, ADR-027), and nothing about any particular game. In the first version players drive all of these by hand, unless the game turns on its rules package, which suggests each step (ADR-029). A rules package helps by offering the same actions a player could, so a game replays without it, and a player can always override it.
Because
Every game gets units, phases and counters without reinventing them, and the log stays readable without package code. The first package, Grimdark Future, is a plain reading of the log that suggests steps, not a general package runtime (ADR-029).
Rejected
An engine with physical things only: every game would rebuild units and phases. Automating one game from the start: rules code shapes the core too early. The first attempt's package runtime: what it collapsed under.
Affects
Players apply the rules, unit, group, phase, counter, mark, priority, item, rules-package, Record
