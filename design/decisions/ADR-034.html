OpenBattle design · Level 3 · Decision

ADR-034: Undo names the action it cancels

Status
Accepted From finding 4 of the decomplecting review, 2026-10-17. Accepted by Porter on 2026-10-17. Built 2026-10-17. Drafted as ADR-033; renumbered, since the package thread took that number for roll subjects.
Context
An undo carries nothing: it cancels whatever is the latest uncancelled action when the host adds it to the log. Its meaning comes from where it lands, not from what the player saw. A player who moves twice quickly and presses Undo while the second move is still on its way cancels the second move, not the one on their screen. Reading the log, an undo also doesn't say which action it cancelled.
Decision
An undo names the log number of the action it cancels. It is refused unless that action is still the latest uncancelled one and was taken by the same player, which are the rules undo already has. The screen sends the number of the action it shows as undoable.
Because
What the player meant is written in the action, so a stale undo is refused instead of cancelling something else, and the log reads on its own. Who may undo and what can be undone stay exactly as they are.
Rejected
Letting an undo cancel any earlier action of the player's, not just the latest: it changes the rule that undo only takes back the latest action, and an older action may have been built on. Keeping the undo empty and having the screen check before sending: the race is between browsers, so only the host's check can see it.
Affects
Record surface (the undo action and check), Screen surface (no visible change)
