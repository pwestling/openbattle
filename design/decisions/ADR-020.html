OpenBattle design · Level 0 · Decision

ADR-020: Limits only where they protect the server or the game

Status
Accepted Porter's call on 2026-10-15; a project principle.
Context
The surfaces had picked caps everywhere: file sizes, dice counts, floors per terrain piece, browsers per game. Most protected nothing.
Decision
A limit exists only to protect the relay server's health or to stop something that would crash a game. Anything else is left unlimited. Where a limit might help, the design leaves it off and the reason goes to Porter as a suggestion.
Because
Pre-emptive caps get in players' way and each one is a rule to explain, test and keep. The first attempt's limits table grew to a dozen entries.
Rejected
Caps chosen for tidiness: the earlier mesh, dice, floor and browser caps, all removed.
Affects
Session surface, Relay surface, Measure surface, ADR-019
