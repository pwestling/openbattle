OpenBattle design · Level 0 · Decision

ADR-018: Proof from the outside, no unit tests

Status
Accepted Porter's call on 2026-10-15; a project principle.
Context
The design needs a way to show that what was built does what the intent says. The first attempt deleted its tests, and the first proposal for this attempt was unit tests for each module.
Decision
No unit tests. Each behaviour in the intent gets a proof: a check that runs the real app in real browsers, does what a person would do (two players on one game, a spectator joining, a host dropping and returning), and confirms what they would see. The proofs run on every change.
Because
Unit tests pin how the code works rather than what it does, so they resist refactoring and can pass while the product is broken. A proof from the outside answers the only question that matters to the person using it, and it maps one to one onto the intent Porter reads.
Rejected
Unit tests per module (the first proposal). No automated checks at all, as in the first attempt.
Affects
Proof from the outside
