Grimdark Future surface

Realizes: Grimdark Future
Status
Proposed Drafted on 2026-10-17 (ADR-029, ADR-030).

One name and two pure functions. Every rules package the app ships would have this same shape; with one package, nothing more general is built.

name: "Grimdark Future"

What a game names when it turns this package on (Record's rules action), and what the screen shows.

readList(text: string, owner: PlayerId, table: Table): { action: Action | null, unread: string[] }

Pre
text is a list as Army Forge exports it as text, pasted or loaded from a file, or typed in the same form: a unit line such as Battle Brothers [5] Q3+ D3+ | 175pts | Fearless, Tough(3) and the weapon lines under it, such as 5x Heavy Rifle (24", A1, AP(1)).
Post
One add to army action for that player, or null if nothing was read. Each unit has its models, on 25 mm round bases unless the line says otherwise, standing in rows along the owner's table edge, as the screen places them today. Each unit gets the counters Quality and Defense; each special rule becomes a mark of that name, or a counter where it has a number (Tough 3). Each weapon becomes an item on a model, with counters Range (none for a melee weapon), Attacks and AP, and its rules as marks or counters (Rending, Blast 3). A line of 5x weapons goes one to each of the first five models; players can move items between models afterwards. A line naming a unit already in the army adds models to it. unread lists the lines it couldn't read, word for word, so the screen can show them.
Fails
Never; what it can't read is in unread. Points, costs and army-building limits are ignored: the app never checks an army.

suggest(log: Log, bodies: Bodies): Suggestion[]

A Suggestion is { for: PlayerId, says: string, take: { actions: Action[] } | { roll: { dice, sides, label } }, about: (UnitId | ModelId)[] }: whose step it is, the sentence shown on its button, what clicking it does, and the pieces it is about so the screen can point them out. bodies is as for Measure's sight.

Pre
The game's rules package is Grimdark Future.
Post
The steps open now, for every player, worked out from the log and its table alone. Where the rules leave a choice, there is a suggestion per choice (one per unit that can activate, one per target in range and sight). Every action in a suggestion carries its says as its note, and a roll's label is its says, so the package finds its own rolls again in the log. Steps that hand the game to the other player include a priority action with a note, such as "Roll 7 blocks, 4+". The same log and bodies give the same list in every browser. Empty when nothing is waiting on anyone, such as before both armies are in.
Fails
Never throws. If a mesh on the table hasn't arrived, suggestions that need line of sight are left out, and one suggestion for nobody says which pieces it is waiting for.

What it keeps on things

All of it is ordinary counters, marks, phase and priority, so players see it in the Army panel and can change it by hand.

What it suggests, built in this order

Each slice ships when its proof passes in two real browsers.

SliceSuggestions
1. ArmiesreadList, used by Add army.
2. Rounds and activationsStart round 1 (the deployment roll-off decides who goes first); Activate one of your units not yet activated; the action to take (Hold, Advance, Rush, Charge); End activation, which marks it Activated and hands priority to the other player, or keeps it if they have nothing left; End round, which scores nothing yet, clears Activated and Fatigued, and starts the next round with whoever finished first.
3. ShootingShoot a target in range and sight, rolling one die per attack with the number to hit; then, for the defender, Roll blocks with the Defense needed after AP and cover; then Remove models, suggesting the casualties within the Tough and hero rules; then morale if the unit fell to half.
4. MeleeCharge targets in reach; the defender's strike back choice; the melee result and its morale test.
5. MoraleThe quality test at half strength, Shaken, routing, and staying idle to recover.
6. Objectives and winnerAt the end of each round, which markers are seized or contested; after round 4, the winner.
7. Spells and reservesCasting and helping with spell tokens; Scout and Ambush arrivals.
