The kinds of action

Every action is one of these nineteen kinds. Adding a kind is an escalation.

KindChanges
joinAdds a player with a name, a colour and the public key of their browser (ADR-022), as base64url of its raw bytes. The player's id must be the one playerIdOf works out from that key.
renameChanges a player's own name or colour.
place terrainAdds a terrain piece, or replaces one with the same id. The piece is a simple solid, or a mesh named by its file's fingerprint, and carries its floors.
remove terrainRemoves a terrain piece.
add to armyAdds new units, models with positions, and groups to a player's army, or more models to one of its units. Each model may name a mesh by its file's fingerprint. Allowed at any point in the game; the first one creates the army.
moveSets the position, facing and floor of one or more models at once, keeping the waypoints each model passed through so everyone can see the path it took.
set asideTakes models off the table, keeping them.
returnPuts set-aside models back at given positions.
groupCreates a group, or changes its name or members.
ungroupDissolves a group. Its units stay.
phaseSets the round, whose turn it is, and the phase name.
counterSets a counter on a target to a number, or clears it.
markTurns a mark on or off for a target.
rollRecords a roll: the dice, the link of the game it was signed in, both random values, and who sent the other value, and their signature over it. The record works out the result from the two values, the same in every browser.
add deckAdds a deck of cards, belonging to a player or the game, either ordered (with its order) or shuffled. Each card may name a picture by its file's fingerprint.
shuffleTurns an ordered deck into a shuffled one.
drawRecords cards drawn from a deck, into the drawer's hand or face up on the table. From an ordered deck, the top cards; from a shuffled deck, the link, both random values, who sent the other one, and their signature, as for a roll; from the values the record works out the cards, the same in every browser. Every draw stays on the table's list of draws; a shuffled draw whose host value does not open its seal is kept and flagged as tampered, as a roll is.
move cardMoves a card between a hand, the table (with a position, face up or down), a discard pile, or back into a deck (on top, at the bottom or at a position if it is ordered).
undoCancels the latest uncancelled action.

newLog(size: { width, depth }, link: string, host: PlayerId): Log

Pre
Width and depth are positive inches. link is the game's link and host the id of the host's browser.
Post
An empty log whose table is that size and bare, for that game and host, with no entries copied from a saved file.
Fails
Never, for valid sizes.

reopen(saved: Log, link: string, host: PlayerId): Log

Pre
link is the new game's link, as Session makes it.
Post
Opening a saved file starts a new game: a log with the new link and host, holding the saved entries as they were and saying how many were copied. The log's link is the given one ending in .N, N the number copied; that is the link the game is shared by, so everyone who has it knows where the copied entries end, and every signature in the new game covers it. They keep the links they were signed with and are not checked again; everything after them must be signed for the new link.
Fails
Never.

check(log: Log, action: Action, by: PlayerId): Problem | null

Pre
None.
Post
null if the action could be appended: everything it names exists, numbers are finite, no group would contain itself, and the player may take it (only the taker can undo; a player renames only themselves); a roll is 1 to 1024 dice of at least two sides, as on the Session surface; a roll or a draw from a shuffled deck can never be undone, since it happens once; a join's id is the one its public key gives, and no other player has that key; in a roll or shuffled draw, the link is the log's, the other value comes from the taker, or from a player other than the host when the host takes it (the host is the log's), its signature is there and not empty, and its seal was not used earlier in the log. The record never checks that a signature is right, so it stays synchronous: Session checks each one against guestStatement as the action arrives and when a saved game loads, and its snapshot lists the rolls and draws that fail. Otherwise a Problem saying why, in plain words.
Fails
Never; problems are returned. Game rules are never checked.

append(log: Log, action: Action, by: PlayerId): Log

Pre
check returns null.
Post
A new log, one longer, with the action numbered next. The old log is unchanged.
Fails
Throws if check would have returned a problem.

checkLog(log: Log): Problem | null

Pre
None. For a log that came from another browser or a file.
Post
null if the log has its link and host, its copied entries are as many as its link says (none unless it ends in .N), and every entry after the copied ones, in order, passes check as it would have when appended, so a host can't slip an exchange from another game in after the copied entries. Otherwise a Problem naming the first action that fails, and why.
Fails
Never.

tableAt(log: Log, upTo?: number): Table

Pre
upTo, if given, is between 0 and the log's length.
Post
The table after applying every uncancelled action up to upTo (the whole log by default). The same log always gives the same table.
Fails
Never, for a log built by append.

fingerprint(table: Table): string

Pre
None.
Post
A short text that is equal for equal tables, so two browsers can tell whether they agree.
Fails
Never.

playerIdOf(publicKey: string): PlayerId | null

Pre
None.
Post
The id a browser's key gives: base64url of the first 16 bytes of the SHA-256 of the raw public key, which publicKey holds as base64url. null if it is not base64url.
Fails
Never.

guestStatement(action: RollAction | ShuffledDrawAction): string

A RollAction is a roll action; a ShuffledDrawAction is a draw action from a shuffled deck.

Pre
None.
Post
The text the other player signs and every browser checks: a JSON object of the action's link, the kind of action, the dice and sides or the deck and count, the seal and the other player's value, its keys in alphabetical order, so the signature cannot be used for any other game or action. The signature fields, the host's value and the roll's label are left out.
Fails
Never.
